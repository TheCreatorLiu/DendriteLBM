# DendriteLBM

GPU-accelerated, two-dimensional dendritic solidification with a multirate D2Q9 multiple-relaxation-time lattice Boltzmann method, implemented in **NVIDIA Warp**.

[![Figure 9: Thermosolutal dendritic solidification under forced convection](figures/previews/figure-09.png)](figures/figure-09.pdf)

*Figure 9. Thermosolutal dendritic solidification under forced convection at Le = 50 and Pe_D = 0.2: phase field, supersaturation, undercooling, and velocity field. Click the image to view the original PDF.*

Companion code for sections **4.1–4.3** of *A unified multirate lattice Boltzmann framework for thermosolutal dendritic solidification* (Yang Liu, Xiaomin Wu, Chengjie Zhan; manuscript supplied as `main0914.tex`).

[Getting started](docs/GETTING_STARTED.md) · [Paper/code alignment](docs/MANUSCRIPT_ALIGNMENT.md) · [Figures 1–10](figures/README.md) · [Validation](docs/VALIDATION.md)

## Three runnable models

| Entry point | Manuscript | Active fields | Flow switch | Figures |
|---|---|---|---|---|
| `thermal.py` | §4.1 | Phase + temperature | `--flow off/on` | 2–4 |
| `solutal.py` | §4.2 | Phase + supersaturation, isothermal | `--flow off/on` | 5–7 |
| `thermosolutal.py` | §4.3 | Phase + supersaturation + temperature, Le = 50 | `--flow off/on` | 8–10 |

Figure 1 describes the numerical workflow. With flow off, the hydrodynamic updates are skipped and the physical velocity remains zero. Flow on advances the flow distributions and applies inlet/outlet boundary conditions. The phase-field auxiliary vector `v` is distinct from physical fluid velocity `u`.

## Get started

Use Python 3.10 or newer and a CUDA-capable NVIDIA GPU with a compatible driver. A Python 3.12 environment is recommended to match the tested interpreter.

```bash
python -m venv .venv
# Windows PowerShell: .\.venv\Scripts\Activate.ps1
# Linux/macOS: source .venv/bin/activate
python -m pip install -r requirements.txt
python thermal.py --smoke --flow off
python thermal.py --smoke --flow on
python solutal.py --smoke --flow on
python thermosolutal.py --smoke --flow on
```

`--smoke` runs a small domain for a short installation check. Omit it to use the full benchmark grid and final manuscript time. First execution compiles GPU kernels and takes longer. CPU checks are available with `--device cpu`; GPU execution is recommended for full cases.

```bash
python thermal.py --flow off
python thermal.py --flow on
python solutal.py --flow off
python solutal.py --flow on
python thermosolutal.py --flow off
python thermosolutal.py --flow on
```

Use `python thermal.py --help` for all options. `--dry-run` prints resolved settings without loading Warp. Every run gets a separate directory under `outputs/`; `--output PATH` selects an empty destination.

## NVIDIA Warp

[NVIDIA Warp](https://github.com/NVIDIA/warp) translates decorated Python functions into native CPU/CUDA kernels. This repository uses `@wp.kernel`, `@wp.func`, device arrays and `wp.launch` for collision, streaming, macroscopic reconstruction and source coupling. The PyPI package is **`warp-lang`**, imported in Python as `warp`.

The tested Warp version is pinned in `requirements.txt`. The official [installation guide](https://nvidia.github.io/warp/v1.16/user_guide/installation.html) covers supported platforms and CUDA driver requirements. The prebuilt wheel supplies the required runtime; building Warp from source is unnecessary for these examples. See [the Warp guide](docs/NVIDIA_WARP.md) for device selection and troubleshooting.

## Reproducibility and scope

The default `--parameters paper` configuration aligns explicit parameter discrepancies with the supplied manuscript. `--parameters supplied` retains the original **flow-script** seed width and relevant transport/viscosity values for comparisons. It is not an archival replay of all five original scripts: the two original no-flow solvers used different boundary paths. See the [complete change record](docs/MANUSCRIPT_ALIGNMENT.md).

The included figures are author-supplied manuscript results, **not outputs regenerated by the short validation runs**. This release has GPU smoke validation; full-duration, full-grid agreement with Figures 2–10 remains to be checked. Section 4.4 and Figures 11–12 are outside this repository's scope.

## Outputs

- `run_config.json`: resolved CLI options, physical parameters, device, package versions and source hashes.
- `run_status.json`: running/completed/failed status and last observed step.
- `tip_velocity.csv`: four axial tip positions expressed as branch lengths, velocities and manuscript nondimensional quantities.
- `fields_*.npz` and `final_state.npz`: phase `psi`, undercooling `theta`, physical `velocity[..., 0:2]`, and supersaturation `U` where active. Array order is `(x, y)`.
- `fields_*.png`: quick-look field images; disable with `--no-png`.
- `fields_*.dat`: optional Tecplot ASCII data; enable with `--dat`.

NPZ files contain macroscopic fields, not all LBM distributions, and cannot restart a simulation exactly. The first velocity sample is NaN because no preceding time interval exists. An unresolved tip crossing is also represented by NaN.
